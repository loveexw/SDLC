# Модель жизненного цикла проекта TaskTracker

## Рассмотренные модели

| Модель | Плюсы | Минусы |
|--------|-------|--------|
| Каскадная (Waterfall) | Простое планирование, полная документация на каждом этапе | Поздняя обратная связь, сложно вносить изменения |
| V-модель | Тестирование планируется параллельно с разработкой | Та же жёсткость, что и у каскадной |
| Итеративная / инкрементная | Рабочая версия после каждой итерации, раннее выявление рисков | Требует контроля объёма каждой итерации |
| Спиральная | Явное управление рисками | Избыточна для небольшого учебного проекта |

## Выбор

Выбрана **итеративно-инкрементная модель** с итерациями, совпадающими с
лабораторными работами курса:

1. Требования (SRS) — лабораторная работа №1.
2. Настройка репозитория и шаблона проекта — лабораторная работа №2.
3. Проектирование (SDD, ADR).
4. Реализация базовых функций (создание, редактирование, удаление задач).
5. Тестирование и выпуск версии 1.0.

Обоснование: проект небольшой, требования могут уточняться по ходу
курса, а каждая итерация заканчивается проверяемым результатом в
репозитории.
