## 1. Введение

### 1.1 Назначение документа
Документ описывает требования к приложению TaskTracker и служит основой
для проектирования, реализации и тестирования. Читатели — разработчик и
преподаватель, проверяющий работу.

### 1.2 Область применения продукта
TaskTracker — настольное приложение для Windows, позволяющее вести список
личных задач: создавать, редактировать, удалять задачи, задавать срок и
приоритет, отмечать выполнение и хранить список в локальном файле.

### 1.3 Определения, акронимы и сокращения
| Термин | Определение |
|--------|-------------|
| Задача | Запись с названием, описанием, сроком, приоритетом и статусом |
| SRS | Software Requirements Specification |
| JSON | Текстовый формат хранения данных |

### 1.4 Ссылки
- ISO/IEC/IEEE 29148:2018.
- Шаблоны курса: https://github.com/BSUIR-SDLC/SDLC

### 1.5 Обзор документа
Раздел 2 описывает продукт в целом, раздел 3 — требования, раздел 4 — способы их проверки.

## 2. Обзор продукта

### 2.1 Перспектива продукта
Самостоятельное приложение, не зависящее от внешних сервисов.

### 2.2 Функции продукта
- ведение списка задач (CRUD);
- приоритеты и сроки выполнения;
- фильтрация по статусу и приоритету;
- сохранение и загрузка списка.

### 2.3 Ограничения продукта
- язык реализации — C++17, среда — Visual Studio 2022;
- ОС — Windows 10/11.

### 2.4 Характеристики пользователей
Один пользователь с базовыми навыками работы с ПК.

### 2.5 Допущения и зависимости
Предполагается наличие у пользователя прав на запись в папку профиля.

### 2.6 Распределение требований
Версия 1.0 — все требования раздела 3.2; синхронизация между устройствами — за рамками проекта.

## 3. Требования

### 3.1 Внешние интерфейсы

#### 3.1.1 Пользовательские интерфейсы
**REQ-INT-001.** Приложение предоставляет консольное меню с пронумерованными командами.

#### 3.1.2 Аппаратные интерфейсы
Не требуются.

#### 3.1.3 Программные интерфейсы
**REQ-INT-002.** Данные хранятся в файле `tasks.json` в папке профиля пользователя.

### 3.2 Функциональные требования
**REQ-FUNC-001.** Пользователь может создать задачу с названием (обязательно), описанием, сроком и приоритетом (низкий/средний/высокий).

**REQ-FUNC-002.** Пользователь может изменить любое поле существующей задачи.

**REQ-FUNC-003.** Пользователь может удалить задачу с подтверждением.

**REQ-FUNC-004.** Пользователь может отметить задачу выполненной и снять отметку.

**REQ-FUNC-005.** Пользователь может отфильтровать список по статусу и приоритету.

**REQ-FUNC-006.** Список задач автоматически сохраняется при каждом изменении и загружается при запуске.

### 3.3 Качество обслуживания

#### 3.3.1 Производительность
**REQ-PERF-001.** Загрузка списка до 1000 задач — не более 1 с.

#### 3.3.2 Безопасность
Не предъявляются (локальные данные одного пользователя).

#### 3.3.3 Надёжность
**REQ-REL-001.** При повреждённом файле данных приложение сообщает об ошибке и создаёт резервную копию файла, не завершаясь аварийно.

### 3.4 Соответствие стандартам
Документация оформляется по СТП БГУИР.

### 3.5 Проектирование и реализация
**REQ-MAINT-001.** Исходный код хранится в Git-репозитории, сборка — через решение Visual Studio без дополнительной настройки.

## 4. Верификация

| Требование | Метод проверки |
|------------|----------------|
| REQ-INT-001, REQ-INT-002 | Демонстрация |
| REQ-FUNC-001…006 | Тестирование (ручные сценарии) |
| REQ-PERF-001 | Тестирование с файлом из 1000 задач |
| REQ-REL-001 | Тестирование с повреждённым файлом |
| REQ-MAINT-001 | Инспекция |
