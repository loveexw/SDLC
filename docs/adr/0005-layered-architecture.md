# Слоистая архитектура: ядро без WinAPI и интерфейс ICrypto

## Контекст и постановка задачи
Требования могут меняться на любом этапе (условие курса), а во 2-м раунде согласования в команду добавлен junior-разработчик. Нужно так разделить код, чтобы изменения затрагивали как можно меньше модулей, логику можно было проверять автоматическими тестами, а задачи — распределять между двумя разработчиками без конфликтов.

## Драйверы решения
- тестируемость бизнес-логики без запуска окон (SYS-13);
- независимая работа двух разработчиков;
- возможность заменить реализацию криптографии (например, для тестов);
- простота понимания кода junior-разработчиком.

## Рассмотренные варианты
- три слоя: ядро (core) без WinAPI, платформа (platform) с CNG/DPAPI, интерфейс (ui); криптография через интерфейс `ICrypto`;
- логика в обработчиках окон (код «внутри форм»);
- MVC с отдельным контроллером для каждого окна.

## Итог решения
Выбран вариант **«три слоя с интерфейсом ICrypto»**: зависимости направлены только к ядру, а ядро получает криптографию через интерфейс.

### Последствия
- Хорошо: правила бронирования и шифрования проверяются модульными тестами без интерфейса.
- Хорошо: junior-разработчик работает в слое ui (профиль, «Мои бронирования», экспорт), не меняя ядро.
- Хорошо: при изменении требований к расписанию или сериям меняется в основном `BookingService`.
- Плохо: дополнительный интерфейс и чуть больше кода, чем при логике внутри форм.

### Подтверждение
Проверка на код-ревью: файлы `src/core/*` не подключают `<windows.h>`; тесты собираются без модуля ui.

## Плюсы и минусы вариантов
### Три слоя + ICrypto
- Хорошо: тестируемость, разделение задач.
- Плохо: немного больше кода.
### Логика в формах
- Хорошо: быстро на старте.
- Плохо: нельзя тестировать без окон, два разработчика мешают друг другу.
### MVC на каждое окно
- Хорошо: строгое разделение.
- Плохо: избыточно для семи окон.

## Дополнительная информация
Системные требования: SYS-13, SYS-17. Связано с ADR-0001 (криптография) и ADR-0004 (интерфейс).
