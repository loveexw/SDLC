# Шифрование персональных данных: AES-256-GCM через Windows CNG

## Контекст и постановка задачи
ФИО, телефон и e-mail пользователей должны храниться на диске в зашифрованном виде. Нужно выбрать алгоритм и его реализацию. Ограничения: C++ и Windows, без сторонних библиотек.

## Драйверы решения
- стойкость, признанная стандартами (NIST);
- обнаружение изменения шифртекста (целостность), а не только конфиденциальность;
- отсутствие внешних зависимостей;
- простота сборки на компьютере преподавателя.

## Рассмотренные варианты
- AES-256-GCM через Windows CNG (bcrypt.dll);
- AES-256-GCM через OpenSSL;
- AES-256-CBC + HMAC-SHA256 (Encrypt-then-MAC);
- собственная реализация AES.

## Итог решения
Выбран **AES-256-GCM через Windows CNG**. Это аутентифицированное шифрование «из коробки», встроенное в Windows: оно не требует установки библиотек и проходит сертификацию FIPS 140.

### Последствия
- Хорошо: шифрование и контроль целостности одним вызовом; поддержка AAD (привязка поля к записи).
- Хорошо: сборка без зависимостей, один exe-файл.
- Плохо: криптографический модуль работает только в Windows. Это смягчается интерфейсом `ICrypto`.
- Нейтрально: требуется уникальный nonce для каждого шифрования — используется случайный 96-битный nonce.

### Подтверждение
Модульные тесты «AES-256-GCM: …» в проекте `SecureBooking.Tests` (функция F11, системное требование SYS-13): расшифровка, разный шифртекст для одинакового текста, обнаружение изменения шифртекста, проверка AAD и неверного ключа.

## Плюсы и минусы вариантов
### AES-256-GCM через CNG
- Хорошо: встроен в ОС, аутентифицированное шифрование.
- Плохо: громоздкий C API.
### OpenSSL
- Хорошо: кроссплатформенность.
- Плохо: сборка и распространение DLL, настройка путей в проекте.
### AES-CBC + HMAC
- Хорошо: классическая схема.
- Плохо: две операции и два ключа, легко ошибиться в порядке; нужно выравнивание.
### Собственный AES
- Плохо: высокий риск ошибок и атак по сторонним каналам; противоречит правилу «не пиши свою криптографию».

## Дополнительная информация
Требования SRS: REQ-SEC-001, REQ-SEC-002, REQ-INT-003. Системные требования: SYS-01. Функция: F01.
