# Хранение данных: текстовый файл с подписью HMAC

## Контекст и постановка задачи
Нужно хранить пользователей, переговорные и бронирования. Объём данных небольшой (сотни записей), приложение однопользовательское и локальное.

## Драйверы решения
- отсутствие внешних зависимостей;
- обнаружение изменения файла вне программы;
- устойчивость к сбоям при записи;
- наглядность: содержимое хранилища показывается на защите.

## Рассмотренные варианты
- текстовый файл с HMAC-подписью;
- SQLite;
- двоичный файл.

## Итог решения
Данные хранятся в текстовом файле `booking.db` (UTF-8, поля разделены `|`). Последняя строка — `HMAC-SHA256` всего содержимого на ключе `Kmac`. Запись идёт во временный файл, который затем заменяет основной.

### Последствия
- Хорошо: файл можно открыть и показать, что ПД зашифрованы, а остальные данные — нет.
- Хорошо: любое изменение файла обнаруживается при загрузке.
- Плохо: файл перезаписывается целиком при каждом изменении. Для учебного объёма это несущественно.
- Плохо: нет одновременной работы нескольких процессов.

### Подтверждение
Модульные тесты «Данные сохраняются и загружаются после перезапуска» и «Целостность: изменение файла базы обнаруживается».

## Плюсы и минусы вариантов
### Текстовый файл + HMAC
- Хорошо: просто, наглядно, без зависимостей.
### SQLite
- Хорошо: SQL, транзакции, индексы.
- Плохо: сторонняя библиотека; целостность файла всё равно пришлось бы контролировать отдельно.
### Двоичный файл
- Плохо: сложнее отлаживать и демонстрировать.

## Дополнительная информация
Требования SRS: REQ-SEC-002, REQ-REL-001. Системные требования: SYS-03. Функция: F01.
